# Generative model audit

One model per run. Everything lives in `examples/gen-models-audit/` of `ersilia-os/chem-sampler` (public repo, branch `chemsampler-update` while it is being built). Results and scratch are gitignored.

## The rules (never break)

1. **Never push, tag or release** anything in an `ersilia-os/<model>` repo, and never change a version, without the user's explicit say-so for that model. Report problems and proposals instead. Releases are the maintainers' decision (output-visible changes are MAJOR in the model template).
2. **Lab nodes only.** Other nodes are billed to the PI. Script 05 refuses nodes outside `CHEMSAMPLER_LAB_CPU_NODES` / `CHEMSAMPLER_LAB_GPU_NODES`; never pass `--allow-any-node` on your own. GPU jobs use the partition and lab GPU nodes with `--nodes=1 --ntasks=1 --gres=gpu:1`, the same header pattern as the user's other array scripts.
3. **Do not poll Slurm.** After submitting, give the job id and the two monitoring commands, then stop; the user says when the jobs are done.
4. **`PYTHONNOUSERSITE=1` for every environment build and run.** Environments must not lean on `~/.local`. There is no conda on the cluster nodes: call the env's interpreter directly.
5. **No cluster address or node name in committed code or docs** (the repo is public). They live in environment variables: `CHEMSAMPLER_SSH_HOST`, `CHEMSAMPLER_LAB_CPU_NODES`, `CHEMSAMPLER_LAB_GPU_NODES` (set in the user's `~/.bashrc`; export them inline in a Claude session if the shell predates them).
6. **Ask before acting.** The repo's CLAUDE.md: plan mode for anything non-trivial, `AskUserQuestion` for choices, session notes in `.claude/` at the end. Scratch work goes in the repo's gitignored `tmp/<topic>/`.
7. **Post to GitHub only after the user has seen the final text.** `gh` is a snap and cannot read files on the shared lab filesystem: pipe the body (`cat final.md | gh issue edit 1919 -R ersilia-os/ersilia --body-file -`) and verify the live body afterwards. Never touch other people's comments.
8. **Never write a SMILES from memory**, and never type a number into a report that a file can give you.
9. **Keep table columns** unless the user names the column to drop.
10. Commit or push in chem-sampler only when asked, staging by file name.
11. **Run every process on the lab workstation** that has the three `CHEMSAMPLER_*` exports in its `~/.bashrc` and shares the filesystem with the cluster, never on a laptop or NUC (builds, smoke tests, scripts 02-07, submission). Send a small script over `ssh` on stdin with `BatchMode` (no password or 2FA can be typed); use `nohup` plus a log under `tmp/<topic>/` for anything longer than a few minutes. A non-interactive ssh does not read `.bashrc`: load only the three `export CHEMSAMPLER_*` lines, and refuse any line containing shell metacharacters. Machine and host names stay out of this file.
12. **Before any push to a model repo, test the push the way CI will run it.** Run the recipe check of step 9 (clean-venv `pip install --dry-run`), then a faithful fetch: ersilia in its own conda env **activated through `conda run -p <env>`** (CI does `conda run -n test ...`; ersilia is installed from git main on every CI run, and its shallow test includes `ersilia fetch <id> --from_dir`), in a scratch home that holds a copy of the real conda config and ToS records, with a scratch `CONDA_ENVS_PATH`. A push starts the whole CI chain (test, S3 upload, image build, image test) and its result is public, so a failure found afterwards costs a red run on the model's repo; a metadata-only push does the same, because CI rebuilds the environment from the recipe. Put all of it on the workstation's local disk, never on the shared network filesystem, and run a model that passes CI (eos80sj) through the same test as a positive control: a test that fails the positive control proves nothing.

## What the audit established (state at the end of the pilot)

- **Benchmark:** 1000 ChEMBL 37 compounds (single component, 250-450 Da, random sample, seed 42), 100 files of 10 (`results/ChEMBL_splits/split_001..100.csv`, column `smiles`). One Slurm task per split plus one extra task re-running `split_001` as `split_001_repeated.csv`.
- **Definitions:** duplicate = same canonical *isomeric* SMILES within a compound; input echo = output equal to its input ignoring stereochemistry (must never happen); null = empty output slot; Tanimoto = Morgan radius 2, 2048 bits, between each valid output and its own input, per compound max / P95 / mean, then mean ± sample std over compounds; retention = share of a compound's outputs keeping the input's Murcko scaffold / generic scaffold / the whole input, plus a breakdown at the most specific level kept.
- **Upstream fixes already pushed (unreleased):** eos9taz, eos633t, eos8fma, eos6ost, eos69e6 (1000 outputs before) and eos57bx (500) now return at most 100 molecules with no duplicates or input echo (eos57bx and eos694w were later rewritten, see the Mol2Mol bullet); eos4q1a and eos9p57 no longer return duplicates (K-Means picked the same molecule for two centres). 14 of the 19 models have output-affecting commits after their latest release (`Critical change after release` in `gen-models-master.csv`).
- **Type scheme (7 classes):** Fragment-seeded growth, Fragment recombination, Scaffold-based, Direct edit, Conditioned translation, Descriptor-conditioned, Reaction-based. Per model in `gen-models-master.csv`.
- **Metadata rule:** a generative model has Output Consistency = Variable unless it is deterministic by design and that is verified (the Ersilia Book defines the field by behaviour: Fixed = same output for the same molecule). eos935d (MetaTrans, beam search, no randomness) stays Fixed, user decision 2026-10-26: repeat, 1 vs 4 threads, one file vs shuffled files and the shipped 2025 example gave 0 differing cells. Still Fixed and to be changed: eos5j3l (eos57bx and eos694w became Variable on 2026-10-23; eos9taz is Variable in the catalog).
- **Pilot eos2401 (reference run):** 30.1% of compounds have at least one null, 14.6% at least ten, 10.3% return nothing; max / P95 / mean Tanimoto 0.22 / 0.18 / 0.13; 99.9% of outputs keep none of the whole input, Murcko or generic scaffold; fails on all single-ring-system and acyclic inputs; 21.5 min per 100 compounds on 4 CPUs; a second run shares only 1.6 molecules per compound but has the same statistics.

## One-time setup

1. `pip install -e ".[audit]"` in the chemsampler conda env: PyYAML for script 03 and `stylia` (pinned in the extra) for the map in script 07; rdkit, numpy, matplotlib and Pillow come with the core dependencies. Without `stylia`, `07 --plots grid` still works but `--plots space` fails on import.
2. Environment variables above in `~/.bashrc`.
3. Seeds: `results/ChEMBL_splits/` exists (script 01 is done; do not rerun).

## Per-model procedure

Do the steps in order; each ends in a stop or a check. Replace `<id>`.

1. **Fetch and build.** `python scripts/02_fetch_generative_models.py --models <id>` then `python scripts/03_build_cpu_envs.py --models <id>`. Check: no WARNING lines left, `PYTHONNOUSERSITE=1 envs_cpu/<id>-cpu/bin/python -m pip check` clean, and the model's own `examples/run_input.csv` runs through `run.sh` with that env first on PATH. `eosvc` exiting non-zero on an empty `model/framework/fit` is normal, not a failed checkpoint. Write the env's `pip freeze` and the build date to `results/<id>/md/env_freeze.txt`: a recipe that leaves dependencies unpinned resolves differently on a later date, and the freeze is what lets the drift be dated and compared. Models with a non-conda step (eos4qda: opam, needs sudo) need the user.
2. **Read the code and write `results/<id>/md/summary.md`**: what the model does, as a numbered list of 5-6 short sentences with no measured numbers (input handling, how it generates, what it filters, output budget, failure modes, number of outputs). Check what it downloads at run time (`from_pretrained`, `hf_hub`, `urlretrieve`, `requests`): if it needs network, copy the cache to `cache/huggingface` (script 04 then sets `HF_HOME` and `HF_HUB_OFFLINE=1`).
3. **Local smoke test and sizing.** `python scripts/04_run_split.py --model <id> --split-id 1` (for a slow model, a 2-compound split in a tmp dir via `--path-to-splits`). Note wall time and memory, and which compounds give empty rows. Choose `--time`, `--mem`, `--cpus` for step 5. Estimates per 10-compound task: eos2401 about 2 min; eos6a1h about 50 min; eos69e6 about 35 min; eos55vx about 3-4 h (about 20 min per compound). Everything else untimed. For a neural model also time 3 compounds with `--cpus 1`: CPU torch scaled badly (ANNalog: 4 threads were only 1.9x faster than 1), so 1 CPU per task usually gives the better throughput. Set `--time` for the slowest compound, not the average (ANNalog draws up to 500 samples for a compound that does not reach 100 hops).
4. **Cluster smoke test.** `python scripts/05_submit_slurm.py --model <id> --array 1 --time ... --mem ...` (use `--dry-run` first). One task; check `results/<id>/csv/split_001.csv`, the `.json` (exit 0, host is a lab node) and an empty `.err`. A first task that fails on imports means the env leaked the user site: fix the env, not the job. Do not poll Slurm while waiting for it: wait for `logs/split_001.json` to appear (a file check, cap about 45 min). The json `host` is a fully qualified name while the node lists hold short names: compare the part before the first dot.
5. **Full array.** `python scripts/05_submit_slurm.py --model <id> --time ... --mem ...` (array `1-101%50`; a finished split is skipped, so the same command resumes after a failure; to change the limit of an array already submitted: `ssh $CHEMSAMPLER_SSH_HOST scontrol update JobId=<id> ArrayTaskThrottle=<n>`). **Give the job id, `ssh $CHEMSAMPLER_SSH_HOST squeue -j <id>` and `sacct -j <id> -X`, then stop.**
6. **When the user says the jobs are done, verify:** 100 `split_NNN.csv` plus `split_001_repeated.csv`, no `*.part.csv`, no non-zero `exit_code` in `logs/*.json`, empty `out/*.err`. Re-run step 5 for missing splits. Count rows with the csv module, not `wc -l` (files may lack a trailing newline).
7. **Evaluate.** `python scripts/06_evaluate.py --model <id>`; re-run whenever more splits arrive (it rewrites `analysis.json` and `md/analysis.md`).
8. **Plots.** `python scripts/07_plot_examples.py --model <id>`; view both images and check blanks, highlights and legend. Use `--outputs` to draw a fresh run instead of the shipped `examples/run_output.csv`.
9. **Quality review**, using 06's counts and the repo: invalid, duplicate, echo, multi-component, atom-map, dummy-atom must be 0 (stereoisomer-only repeats are allowed under the duplicate definition; report them); `run_output.csv` shape vs `run_columns.csv` and metadata Output Dimension; Description / Interpretation / Tag vs the measured behaviour; Output Consistency must be Variable unless deterministic by design and verified (repeat run, 1 vs several threads, shuffled batch composition: 0 differing cells); output size vs description; `gh run list -R ersilia-os/<id>` for red workflows; commits after the latest release (`gh api repos/ersilia-os/<id>/compare/<tag>...main`). **Recipe check** (the model must still build tomorrow): (a) list which entries of the install recipe (`install.yml`, or the Dockerfile's `RUN pip install` lines) are pinned and which dependencies are left to float (a top-level pin does not pin what its dependencies pull in); (b) in a clean venv run the recipe's install steps in order, the last ones with `pip install --dry-run`, and compare the plan with `env_freeze.txt`: a pinned package that a later step would replace is a defect today even when CI is green; (c) look at the date of the model's last CI run next to the date of the benchmark: CI that has not run since is not evidence that a rebuild works. List problems with evidence; propose fixes; do not push them.
10. **Optional: CPU phase profile and GPU test.** Only when the model has a neural sampling step. Time each phase on one split on a CPU node first (wrap the model's calls with timers, two passes in one process, watch for one-off pool or model-load costs). If the GPU-capable step is more than about half of the time, build a GPU env (the CPU env's `pip freeze` without torch, then the CUDA wheel of the same torch version; the lab GPU nodes' driver supports CUDA 12.8) and compare CPU, 3090 and H200 on `split_001` plus a 100-compound equivalence run checked with script 06. `tmp/eos2401-gpu/` has the harness, job templates and `build_assessment.py`. Report the model-side change as a proposal.
11. **Fold into the status table.** Update the model's row in `gen-models-master.csv` if its release, flag or size changed, then edit the LIVE body, not a regenerated one: `tmp/issue-1919/build_draft.py` is stale (since 2026-10-22 the live body was extended by hand-run scripts: the substructure column, the Direct edit rows, the eos84nf rename), so its output differs from the live issue in many places. Fetch the live body (`gh api repos/ersilia-os/ersilia/issues/1919 --jq .body`), run `tmp/issue-1919/substructure_column.py <id>` on a node, then `tmp/issue-1919/fill_row.py <live> <new> <id> <bullet.txt> [gpu_cell]` (fills the row, bumps the counter, inserts the bullet; `tmp/issue-1919/eos935d_edit.py` is a worked example that also changes two wording points), diff the new body against the live one, show the user the diff, and post it only after approval (rule 7).
12. **Session notes.** Append what changed, the real numbers, mistakes and open items to the dated `.claude/*-session-notes.md`.

## Pitfalls already paid for

- **Reading a model's CI log:** `gh run view --log` returned 0 lines for eos935d; list the jobs with `gh api repos/ersilia-os/<id>/actions/runs/<run>/jobs` and read one with `gh api repos/ersilia-os/<id>/actions/jobs/<job>/logs` (the "Consistency Summary Between Ersilia and Bash Execution Outputs" table in the model-test job compares the served output with the bash output column by column). `sacct` exists only on the cluster login host (`ssh $CHEMSAMPLER_SSH_HOST sacct ...`), not on the workstation.
- **User-site leakage:** pip skipped packages found in `~/.local`, so 10 of 19 envs lacked jinja2, flask, sqlalchemy, ...; they failed on cluster nodes. Script 03 now sets `PYTHONNOUSERSITE=1` and warns on `pip check`.
- **`conda run` buffers output and does not exist on the nodes:** use `<env>/bin/python` (scripts 04 and 05 do).
- **`--nodelist` with `--nodes=1`** (several lab nodes listed) works as "any of these" on this cluster; the user's own array scripts use it.
- **`gh` snap cannot read paths on the shared lab filesystem:** `--body-file -` with stdin.
- **`pkill -f` with a pattern that appears in your own command line kills your shell:** kill by PID.
- **`--help` on a script without argparse runs the script** (script 01).
- **RDKit `MakeScaffoldGeneric` raises on hypervalent atoms** (P, S become 5-6-valent carbons): 06 treats that scaffold as having no generic form.
- **Examples files may lack a trailing newline:** count rows with csv.
- **A model's example inputs can include compounds it cannot handle** (empty rows are data, not errors).
- **Safe/joblib pool start-up** (eos2401): the first call that decodes more than 100 sequences, or the substructure filter, starts a process pool (11 s on the CPU node, 16 s on a GPU node); serial replacements remove it.
- **`analysis.json` goes stale** when splits are added; re-run 06 before quoting numbers.
- **Disk:** the shared home filesystem is about 99% full; a CUDA env is 11 GB. Reuse caches, do not copy envs.
- **A model can ignore its input without raising anything** (eos8zvb: an `AttributeError` swallowed by `except Exception: continue` sent every input to a benzene fallback): in the quality review compare each output's Tanimoto to its own input with its Tanimoto to a shuffled other input (`tmp/eos8zvb/input_dependence.py`); equal values mean the output does not depend on the input. Also call the model's own helper on a few trivial inputs and look at what it returns, and list which fragments / steps raise inside a bare `except` (eos8zvb had a second one: a `KekulizeException` made it skip the larger fragment, e.g. a purine, of a third of the inputs).
- **SMILES-unique is not diverse** (eos8zvb: the growth generator yields every intermediate stage, so about 80% of the 100 outputs are a substructure of another output, about 20 independent molecules per compound): in the quality review also report the share of outputs contained in another output of the same compound and the mean pairwise Tanimoto of the top 5 (`tmp/eos8zvb/nested_stages.py`).
- **A similarity ranking that selects inflates every similarity metric** (eos4qda: the 100 outputs were the best of at least 300,000 candidates by Tanimoto, so max Tanimoto 0.91 and 29% of outputs containing the whole input described the selection, not the generator): in the quality review check whether a model ranks to select or only to display, compare the similarity of a random pick among the same candidates, and read the model's git history and its shipped example outputs for when the numbers changed (`git show <commit>:model/framework/examples/run_output.csv`).
- **Slurm tasks run the clone's code when each task starts:** cancel the array before editing, pulling or checking out the model clone, and archive its partial `results/<id>/{csv,logs,out}` (to `tmp/`) before re-submitting; otherwise the array mixes old and new code.
- **Pending tasks can wait a long time:** the lab CPU nodes are shared and were nearly full; a short array (eos8zvb tasks take about 20 s each on a node) may sit pending behind longer ones.
- **Script 03 with another env's `bin` first on PATH installs into that env** (eos80sj: `conda run -p <prefix> pip` used the chemsampler env's Python 3.10 pip, so torch and seven dependencies landed in chemsampler and pip then refused `numpy==2.5.3`). Run 03 with `PATH=<conda base>/bin:/usr/local/bin:/usr/bin:/bin` and the chemsampler python by absolute path, and after a build check `pip list` of the model env. If a stray run did install into another env, remove only what it added: the dist-info timestamps and `pip show` "Required-by" tell which packages those are.
- **`import stylia` deletes matplotlib's cache directory** (the real one, shared by every matplotlib process of the user). Script 07 wraps the import in `mock.patch("shutil.rmtree")`; do the same in any ad hoc script, and never test it against the real cache dir (use a throwaway `MPLCONFIGDIR`).
- **A model may return multi-component outputs when its wrapper does not filter them** (eos80sj: 1 of 1000 outputs of split 1 had a "."): the quality review counts them; the fix is model-side, proposed and not pushed.
- **A recipe that pins only top-level packages breaks without any change to the repo** (eos2401: the Dockerfile ran `pip install transformers==4.57.6`, then `pip install safe-mol==0.1.14`; safe-mol's unpinned `datasets` resolved to 5.1.0, released 2026-10-05, which needs `huggingface-hub >= 1.31` while transformers 4.57.6 needs `< 1.0`, so pip replaced transformers with 5.x, which has no `beam_constraints`, the module `mol_gen.py` imports, so a rebuild today gets a model that cannot start; the benchmark env built on 2026-09-29 had the working set). It WAS the cause of the red CI run of 2026-10-19: on the workstation's local disk, ersilia's own `fetch --from_dir` failed with the current Dockerfile (the fetched env had transformers 5.20.1, huggingface_hub 1.33.0, datasets 5.1.0; importing the model code gave `No module named 'transformers.generation.beam_constraints'`) and passed with a Dockerfile that installs the benchmarked pins in one call (`transformers==4.57.6 tokenizers==0.22.2 huggingface-hub==0.36.2 datasets==2.14.4 rdkit==2026.3.6 safe-mol==0.1.14`), while a model that passes CI (eos80sj) passed the same test. Install the pinned packages in ONE pip call so the resolver honours them together, and pin the transitive packages that matter (Hugging Face stack, rdkit, torch).
- **Reproducing ersilia's fetch: use `conda run -p <ersilia env>`, never the env's `bin` on PATH.** With ersilia's `bin` first on PATH, `python` and the pack tool resolve to ersilia's own env after `conda run -n <model>`: the model's dependencies land in ersilia's env and the model env stays empty (a false failure). An isolated HOME also needs a copy of the real `~/.condarc` and `~/.conda/tos`, otherwise `conda create` refuses to run (Terms of Service); use a scratch `CONDA_ENVS_PATH`, because a fetch starts by deleting the conda env named after the model.
- **Run fetch tests on a local disk and always include a model that passes CI as a positive control.** On the shared network filesystem every model failed ersilia's fetch check, even eos80sj, which passes CI: environments there start their server in 10-15 s and `ersilia run` probes only about 5-10 s after `ersilia serve` returns (`_ensure_ready(..., attempts=10)`, `ersilia/utils/ports.py`), then reports "Model <id> is not responding"; importing numpy and torch took 9.7 s cold from that disk. With the conda envs, the scratch HOME and the ersilia env all on the workstation's local disk the servers answered in 6-8 s and eos80sj passed. An explanation built on a test that fails the positive control is not evidence (eos2401 was misdiagnosed twice this way: first as the Dockerfile drift on a broken harness, then as ersilia's probe window).
- **A green CI result is dated, not permanent.** CI installs ersilia from git main on every run (ersilia changed `fetch` and `run` on 2026-09-26: `ersilia run` now exits 1 when a model returns nothing, the shallow test gained a fetch check; for ersilia's deterministic example #1 and #3 eos2401 and eos4qda return empty rows; ersilia issue #1937 is open). Quote the date of the last run, not "green".
- **Sampling until N distinct molecules needs a round limit and a draw size, and both cost time or rows.** eos57bx (two priors, transformer) takes about 7.5 min per compound on 2 CPUs; with 150 draws per round some compounds end below 100 (the user chose 150 over 300 because the model is Variable and can be run again). Draw sizes 150, 300 and 500 were compared on split_001 before choosing (`tmp/conditioned/tune/`).
- **Ersilia's image test did not time the larger sizes of a slow model.** eos57bx needed 260.74 s for one input and its 'Computational Performance 2' to '5' were stored as -1.0 (README: `100 inputs: -1`); the cause is not read from ersilia's code, only seen in the CI log (run 40034824622).
- **REINVENT's vocabulary rejects atoms outside its training tokens** (P, B, As, Se, `[S+]` for Mol2Mol): `Mol2Mol failed on ...: ... is not part of the tokens`. Catch it per input, print it to stderr and return an empty row, otherwise one such compound loses its whole file of 10.
- **Plot script 07 needs stylia, which only the chemsampler env on the workstation has.** On a lab node, run it with `envs_cpu/eos1klk-cpu/bin/python` (it has lazychemvis, matplotlib, rdkit, Pillow) and `PYTHONPATH` pointing at a directory made with `pip install --no-deps --target <dir> stylia==1.0.1`; scripts 06 and the quality review run with `envs_cpu/eos80sj-cpu/bin/python` (rdkit, numpy). The workstation's chemsampler env path does not exist on the nodes (exit 127).
- **A conda env used without activation can load the node's older `libstdc++`.** Two Python 3.10 envs (eos57bx, eos694w) ran on the workstation but failed on the lab nodes in 6 s with `CXXABI_1.3.15 not found` while importing `sqlite3` (conda's `libicu` needs a newer `libstdc++` than the node's system one). Script 04 now puts `<env>/lib` first on `LD_LIBRARY_PATH` for the model process; any hand-made test run outside script 04 needs the same, and script 02 needs `eosvc` on PATH (the chemsampler env's `bin`) while script 03 must not have it first.
- **Delegating code reading:** subagents cannot write files (the harness refuses); tell them to return the text, then spot-check constants, `except` blocks, seeds and network calls against the code before saving. Background ssh: use `ssh -n` with `setsid nohup ... < /dev/null &` and a log on the shared filesystem, or the tool's background mode, or the call stays open until the job ends.
- **A push starts two CI workflows:** "Test and upload model" (test, S3, image builds) and then "Test model image" whose head is the bot's follow-up commit, not yours; its arm64 job takes about 70 min. Watch it by run id.

- **The cluster login is not reachable from the NUC; submit through the ssh hop and run nothing there.** The user's rule of 2026-10-23: quick checks and tests are Slurm jobs on the lab CPU nodes, not the lab workstation. `tmp/descriptor_fix/hop.sh <script> [args]` pipes a local script over ssh to the host that holds the `CHEMSAMPLER_*` variables; the script only writes an sbatch file and calls `sbatch` (`submit_tests.sh`, `submit_cmd.sh`). Log and `.done` files land on the shared filesystem and are read from the NUC.
- **The NUC's view of the shared filesystem returns EPERM now and then** (`bash script.sh`, `cmp`, `rm` or `cp` on files the cluster just wrote, creating a file in `examples/gen-models-audit/`, which makes the Edit tool fail on SKILL.md): retry after a few seconds, write in place, or do the check in a one-task job.
- **Ersilia's runner reports stderr output as an error:** keep per-input summaries on stdout and only failures on stderr. tqdm bars still go to stderr in eos69e6 (pre-existing).
- **`ersilia_pack_utils.read_smiles` raises `IndexError` on a bare blank input line** (it does `r[0]` for every csv row). Ersilia writes an empty input as `""`, which is fine; eos69e6 and eos8vud read the file themselves and keep a blank line as an empty row.
- **A fixed seed can hide a failure mode.** SQUID (eos8vud) spends its whole attempt budget (100) on the first of 5 conformers, so with random seeds a compound returns nothing when that conformer is bad (outputs are all-or-nothing per compound); `reps_per_seed=2` rotates the budget over the conformers. A test that passes on three hand-picked examples (the old shipped example) says nothing about coverage: count compounds with at least one output over 30 compounds.
- **Per-attempt `except` swallows a `NameError` as an ordinary failure** (SQUID `unconverged += 1` on a name that is never defined, three places in `general_utils.py`): it behaved as "failed to converge" by accident; define the intent (raise) instead of defining the counter, which would let half-built molecules through.
- **Ruff 0.16.7's default rule set flags many pre-existing lines in the model repos (BLE001, UP031, C408 ...).** The model repos have no ruff config: use the org's `canonical-ruff.toml` (repository-auditing skill, `references/`) and check that no file gets worse (format-diff and check counts before and after) instead of reformatting whole files.
